# Primer Spec

A Jekyll "remote theme" that adds a sidebar, subthemes, and other features to
GitHub Pages project specs. It's used by several courses at the University of
Michigan, so backwards compatibility for already-built sites matters (see
Versioning below).

Full architecture notes: `docs/DEV_README.md`. Contribution workflow and
release process: `docs/CONTRIBUTING.md`.

## Stack

- Jekyll (Ruby) for the static site / theme itself (`_layouts`, `_sass`,
  `index.md`, `demo/`).
- TypeScript + Preact, bundled with webpack, for the client-side plugin in
  `src_js` (sidebar, subtheme picker, table of contents, etc.). Compiled
  output is committed to the versioned `assets/` directory.

## Commands

- `script/bootstrap` — one-time setup of Ruby + npm dependencies, installs
  the pre-commit hook.
- `script/server` — run the Jekyll dev server at http://localhost:4000 with
  live rebuild.
- `npm run lint` / `npm run lint:fix` — ESLint on `src_js` (`--max-warnings=0`).
- `npm run format` — Prettier.
- `npm run test:js` — Jest unit/integration tests.
- `script/cibuild` (`npm test`) — what CI runs: full site build + lint +
  format check + type check + Jest. Run this before opening a PR.

## Repo structure

- `src_js/` — TypeScript/Preact source. `main.tsx` is the entry point;
  `components/` holds Preact components; `subthemes/` holds subtheme
  definitions and CSS-variable logic; `Config.ts` holds constants.
- `_sass/spec/` — SCSS for the sidebar and subthemes (via CSS variables).
- `_layouts/spec.html` — the Jekyll layout consumers opt into; keep its
  output stable since it's covered by the backwards-compat guarantee below.
- `assets/` — **versioned**, compiled JS/CSS output. Don't hand-edit; it's
  regenerated by `script/cibuild`/release tooling.
- `demo/` and `index.md` — demo pages used to manually exercise theme
  features; not automated tests.

## Conventions

- Base PRs on `develop`, not `main`. `main` only moves during release syncs
  (see `docs/CONTRIBUTING.md`) and is what's currently live on course sites.
- Every PR (except `noop` doc-only changes) needs a semver label
  (`patch`/`minor`/`major`) and, if required, a version bump via
  `script/version bump <level>` in the same PR — see "Bumping the version in
  Pull Requests" in `docs/CONTRIBUTING.md`. When unsure which level applies,
  ask rather than guessing.
- Don't modify `assets/` by hand — it's regenerated, and premature changes
  break the backwards-compatibility guarantee for already-built sites.
- 2-space indentation, single quotes, trailing commas — enforced by
  Prettier/ESLint (`.prettierrc`, `.eslintrc`); run `npm run lint:fix` /
  `npm run format` rather than hand-formatting.
